# FE1 — Storefront Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the demo app's plumbing with the production foundation: a typed API client generated from the backend contract, auth (Firebase + test sign-in), i18n (EN/ខ្មែរ), routing with layouts, the design tokens and UI primitives, the header/footer shell with the live bag count and menu. Delete all mock data, StoreContext and the old pages. At the end the app boots against the real API with the shell, 404, and placeholder routes that FE2–FE5 fill in.

**Architecture:** Feature folders under `src/` as in the spec §5. The API client is a thin typed fetch wrapper over types generated by `openapi-typescript`; server data goes through TanStack Query; auth state lives in an `AuthProvider` that exposes `getToken()` to the client; UI primitives live in `src/ui`.

**Tech Stack:** React 19, Vite 8, Tailwind 4, TypeScript 6, React Router 8, TanStack Query 5, Firebase 13 (web), openapi-typescript 7 (dev), MSW 2 (dev), @fontsource Barlow Condensed / Plus Jakarta Sans / Noto Sans Khmer, Vitest + Testing Library, Playwright 1.63 (pre-installed browser).

**Spec:** `docs/superpowers/specs/2026-11-26-frontend-production-design.md` (§3 constraints, §5 architecture, §6 visual direction); backend contract `../sport-backend/docs/api/openapi.json`.

## Global Constraints

- Every request: `credentials: 'include'`; JSON; `lang` query param on catalog/cart/order reads (`en` | `km`).
- Errors from the API arrive as `{error:{code,message,details?}}` → `ApiError(code, status, message, details)`.
- 401 with a signed-in user → refresh the Firebase token once and retry; a second 401 → sign out and keep the guest bag.
- No server data in localStorage. localStorage only holds UI preferences (`sc.lang`).
- Money arrives in integer cents; format with `formatUsd(cents)` → `$95.00`; KHR → `៛389,500` with grouping; dates in Asia/Phnom_Penh.
- Tokens (exact hex): paper `#FDFCF9`, stone `#EAE7DF`, obsidian `#0E1113`, graphite `#5A5D57`, vermilion `#C8232C`, cobalt `#032EA1`, brass `#B8933B`. Fonts: Barlow Condensed 700/800 (display), Plus Jakarta Sans 400/500/600 (body, 16 px, line-height 1.55), Noto Sans Khmer (when `lang=km`, line-height 1.7). Focus ring 2 px obsidian with 2 px offset.
- Copy: sentence case; no all-caps eyebrows; no "A · B · C" strings; buttons name the action.
- Screens: after each UI task, screenshots at 390×844 and 1366×900 against a running backend (`AUTH_TEST_MODE=true`, fake payments, seeded dev DB), reviewed before commit; screenshots stay in the scratchpad.
- Vite dev proxy `/v1` → `http://localhost:3000` and `/assets` stays local (`public/assets`).

## Review Focus

1. **API down or slow:** the header still renders (bag count hidden, menu fallback to static categories), pages show error + Retry, never an endless skeleton. Pinned in Task 5 (`Skeleton` timeout test) and Task 6 (header with failing `/cart`).
2. **Expired Firebase token mid-session:** one refresh + retry, then sign-out without losing the guest bag. Pinned in Task 2.
3. **Khmer text:** font switches with `lang=km` and long Khmer labels don't overflow the 390 px header. Pinned in Task 3 (test) and Task 6 (screenshot).
4. **Unknown route / old hash URLs (`/#/products/x`)** → 404 page, or redirect old hash product links to `/p/x`. Pinned in Task 6.
5. **Test sign-in leaking to production builds:** the test adapter is only bundled when `VITE_AUTH_TEST_MODE=true`. Pinned in Task 4 (build-flag test).

### Task 2: Typed API client

**Files:** `src/lib/api/client.ts`, `src/lib/api/errors.ts`, `src/lib/api/index.ts`, `src/test/msw.ts`, `src/lib/api/client.test.ts`

**Interfaces — Produces:**
```ts
export class ApiError extends Error { code: string; status: number; details?: unknown }
export interface ClientConfig { baseUrl: string; getToken: (forceRefresh?: boolean) => Promise<string | null>; onUnauthorized: () => void; lang: () => 'en' | 'km' }
export function configureApi(cfg: ClientConfig): void;
export function apiFetch<T>(path: string, opts?: { method?: 'GET'|'POST'|'PUT'|'PATCH'|'DELETE'; query?: Record<string, string | number | boolean | string[] | undefined>; body?: unknown; headers?: Record<string,string>; signal?: AbortSignal; withLang?: boolean }): Promise<T>;
export type Paths = import('./types.gen').paths;  // re-export for endpoint typing
```
- [ ] Tests (MSW):
  - sends `credentials: include` (assert via `request.credentials` in the handler) and `Authorization: Bearer t1` when `getToken` returns `t1`; no header for guests;
  - arrays become repeated params (`brand=a&brand=b`); `undefined` dropped; `lang=km` added when `withLang`;
  - a 409 `{error:{code:'insufficient_stock',message:'Only 2 available',details:{available:2}}}` → `ApiError` with those fields;
  - a non-JSON 502 → `ApiError('network', 502, 'The shop is having trouble reaching the server. Try again.')`;
  - a network failure (`HttpResponse.error()`) → `ApiError('offline', 0, …)`;
  - 401 → `getToken(true)` called once, request retried, second 401 → `onUnauthorized` called and the `ApiError('unauthenticated')` thrown;
  - 204 → `undefined`.
- [ ] FAIL → implement → PASS → suite. Commit `feat: typed API client with token refresh and error mapping`.

### Task 4: Auth (Firebase phone + Google, test sign-in)

**Files:** `src/lib/auth/{firebase.ts,AuthProvider.tsx,testAuth.ts,types.ts}`, `src/lib/auth/AuthProvider.test.tsx`, `vite.config.ts` (define), `.env.example`

**Interfaces — Produces:**
```ts
export interface SessionUser { id: string; phone: string | null; email: string | null; fullName: string | null; role: 'customer'|'staff'|'admin'; staffBranchId: string | null; phoneVerified: boolean }
export interface AuthAdapter { onChange(cb: (signedIn: boolean) => void): () => void; getToken(force?: boolean): Promise<string | null>; signOut(): Promise<void>;
  startPhone(e164: string, recaptchaContainerId: string): Promise<{ confirm(code: string): Promise<void> }>; google(): Promise<void>; linkPhone?(e164: string, containerId: string): Promise<{ confirm(code: string): Promise<void> }>;
  testSignIn?(token: string): Promise<void> }
export function AuthProvider(props: { adapter: AuthAdapter; children: ReactNode }): JSX.Element;
export function useAuth(): { status: 'loading'|'guest'|'member'; user: SessionUser | null; cartMerged: { mergedLines: number; cappedLines: number } | null; adapter: AuthAdapter; refresh(): Promise<void> };
export function createAuthAdapter(): AuthAdapter; // firebase, or test adapter when import.meta.env.VITE_AUTH_TEST_MODE === 'true'
```

- After any sign-in: `POST /v1/auth/session` → `user`, `cartMerged`; invalidate the `['cart']` query. Sign-out: `queryClient.clear()` except catalog queries.
- The test adapter keeps the token in memory only (`test:<uid>:<phone|->:<email|->`).
- `configureApi({ getToken: adapter.getToken, onUnauthorized: signOut })` is wired here.
- [ ] Tests (fake adapter + MSW): sign-in calls `/auth/session` and exposes the user; `cartMerged` surfaces; `onUnauthorized` signs out; status `loading` → `guest` without a token. Build-flag test: `createAuthAdapter()` returns the Firebase adapter when the flag is unset (mock `import.meta.env`).
- [ ] FAIL → implement → PASS → suite. Commit `feat: phone and Google sign-in with session sync and test sign-in for e2e`.
