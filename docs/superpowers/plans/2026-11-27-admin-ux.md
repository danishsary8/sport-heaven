# Admin & staff UX, KPI charts, product photos, product import, motion polish

Spec: the owner's request of 2026-11-27 (conversation). Summary of what it asks for:
- Admin and staff flows that are easy, not complicated: manage products by selecting (bulk), editing quickly.
- KPI cards and charts on the overview.
- Import new products with validated, correct data.
- Edit product photos: each product has a main photo and a second (different pose) photo used for the hover on cards.
- Smooth, glitch-free motion on buttons and pages; no animations that restart.
- The home hero carousel must stay exactly as it is (do not edit HeroCarousel, heroSlides or the hero CSS).

Repos: frontend `sport-heaven` (this repo), backend `../sport-backend`. Branch `claude/wizardly-hypatia-gfmab2` in both.

## Global constraints
- Same visual language as the shop: paper/stone/obsidian, vermilion only for buy actions, Barlow Condensed display, Plus Jakarta body.
- Admin is a lazy chunk: initial storefront JS must stay under the 150 kB budget (`npm run build`).
- Products endpoints stay admin-only (`requireRole('admin')`); overview + sales are staff and admin, branch-scoped for staff.
- No new external services. Uploaded photos are stored in Postgres and served by the API.
- Every task: backend `npx vitest run <file>`; frontend `npx vitest run <file>`; both suites green at the end.

## Task 2: Backend — photo upload stored in Postgres
Files: migration `drizzle/0011_media_files.sql` + journal/snapshot, schema `media_files`, router `src/modules/admin/mediaRouter.ts` (+ public GET), `src/modules/catalog/view.ts` `assetUrl`.
- `POST /v1/admin/media` (admin, raw body `image/jpeg|png|webp`, ≤ 4 MB) → `{ path: "media/<uuid>.<ext>", url }`. Rejects other types (415) and empty/oversize bodies (400/413). Checks magic bytes match the type.
- `GET /v1/media/<uuid>.<ext>` public, `Cache-Control: public, max-age=31536000, immutable`, correct content type, 404 when missing.
- `assetUrl(base, path)` returns `<PUBLIC_API_URL>/v1/media/...` for `media/` paths so storefront cards show uploaded photos.
- Test: upload a tiny PNG, fetch it back byte-for-byte; reject text/plain; PUT images with the returned path; catalog listing shows the media URL.
